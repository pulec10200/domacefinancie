# Document pipeline

Native selection or stabilized folder detection → file signature/size validation → SHA-256 → immutable archive copy → document/job transaction → persistent queue → PDF text extraction or image decoding → local QR (PDF raster pages included) → supported adapter result or manual eKasa state → local OCR when needed → structured proposals and provenance → needs_review → preview, correction and explicit confirmation → payable/expense/contract and completed job.

Original bytes stay in Archive. Duplicate imports return the existing ID. Startup recovers interrupted running jobs; retry/cancel controls preserve originals and show readable failures. Queue claiming is transactional across connections. The separate Electron Node child serializes parsing/preview, enforces a 512 MB JS heap and 10-minute processing / 90-second preview timeout, and can be killed/restarted. Native allocations are not bounded by the JS heap; page/pixel limits apply separately.

Limits: 30 MB file, PNG/JPEG/WebP, 40 million image pixels, 100 PDF pages, 12 million raster pixels per page. PDF text is used before OCR; scanned pages use native canvas and Tesseract with bundled slk/eng data. No model download is needed at installed runtime. QR content, verification response and OCR are stored separately. QR does not prove authenticity. The production eKasa provider requests manual verification; official service checks can be recorded as user attestations without inventing automatic success.

ExtractionService retains source/method/page and actual confidence only when available (current text/OCR proposals leave confidence null). Labelled amounts/dates are conservative proposals; conflicting sources are shown and do not receive an invented confidence percentage. AI proposals are additional sources. Missing dates are never fabricated. User confirmation appends immutable history and current confirmed values; receipt items can be edited and compared against the total.

Confirmation is idempotent. A receipt requires an account and creates one expense. An invoice can create a new payable or replace an existing unpaid estimate, retaining its original estimate. A contract creates a contract plus optional rule; the document itself is not a payment. Paid invoice-backed history is preserved.

Folder watching uses five-second write stabilization, an initial scan and minute rescans. Files remain in their source folder and are never moved or deleted by the watcher. Inbox/Processed/NeedsReview/Failed folders are reserved local organizational directories; authoritative state is in SQLite. Only one folder is active at a time. Externally synchronized Drive/OneDrive/rclone folders work through this same adapter; see integrations/LOCAL_FOLDERS.md.
