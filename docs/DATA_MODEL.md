# Data model

Migration 1: accounts, transactions, obligation_rules, payables, payment_allocations, documents, processing_jobs, notifications, settings, audit_events. Migration 2: document_confirmations. Migration 3: households, categories, assets, contracts, budgets, obligation_changes, receipt_details, receipt_items, extraction_results, ai_configurations, ai_routes, ai_usage, and additive account/transaction/rule/payable/job fields and indexes.

Accounts belong to a default local household. Asset, contract, document, rule, payable and transaction are distinct entities linked by UUIDs/foreign keys. Contract metadata is validated structured JSON. Budget uniqueness is month/category; category parents cannot form cycles. Parent budgets include descendants and linked historical transactions after a category rename. Amounts are safe integer EUR cents; AI price estimates are integer EUR micro-units with explicit user-entered per-million-token rates.

Transfers are one transaction referencing distinct accounts. One request UUID is idempotent. Transactions retain voided history; restoring them rechecks precision. Payments create a matching expense/income transaction plus allocation atomically, reject overpayment, and carry asset/contract attribution. Allocated payments cannot be edited or voided as unrelated transactions. Recurrences retain a unique (rule_id,period_due) anchor even when an invoice changes the actual due date; the original (rule_id,due) constraint is also retained. Changes never rewrite paid or invoice-backed history. Invoice matching retains estimated_amount and stores the confirmed actual amount/document link.

Document hashes and archived paths are unique; confirmation is unique by document_id. The polymorphic confirmation entity ID remains application-validated, not a cross-table foreign key. Original OCR/eKasa and user confirmation events remain separate; extraction results contain source, method, optional page/confidence and confirmed value. No fabricated confidence is added. Jobs retain attempts/progress and are claimed transactionally; interrupted jobs are retryable. Notifications are deduplicated by payable/calendar day; preferences plus due dates define the durable reminder schedule.

AI configurations contain safe JSON configuration and an OS-encrypted secret BLOB, never a plaintext key. Routes reference provider configurations. Usage stores token counts when supplied; preflight reservations remain conservative on unknown/failed responses. JSON export omits encrypted secrets. A full backup includes encrypted BLOBs; on another OS/profile, keys may need re-entry.

Migrations are transactional and reject newer unknown schema versions. Before upgrading an existing file DB, VACUUM INTO creates a unique .schema-<version>-<UUID>.backup.db safety copy. No update deletes the database. Tests create a genuine version-1 fixture, upgrade it and reopen existing data. Backup manifests hash every copied database/archive file; restore validates checksums, SQLite and foreign keys before activation.
